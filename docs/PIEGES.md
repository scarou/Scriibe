# Pièges déjà rencontrés

À consulter quand quelque chose résiste, pas à lire à chaque reprise (sorti de `REPRISE.md` en S08). Les règles de travail sont dans `CLAUDE.md`.

## Compilation, tests et outils

- `"/a/b"` et `Path::new("/a").join("b")` ne sont pas égaux sous Windows : construire les fausses listes de fichiers avec `join`.
- Programmes en `.exe` sous Windows. Python n'est **pas installé** sur le PC de Christophe : modifier les fichiers avec les outils de l'éditeur ou avec Node (les scripts `tools/*.py` se lancent depuis une session cloud).
- Les fichiers du dépôt sont en fins de ligne CRLF sous Windows : un remplacement de texte sur plusieurs lignes doit en tenir compte (un script qui remplace `\n` échoue sans bruit).
- PowerShell 5.1 écrit un BOM avec `Set-Content -Encoding utf8` : `settings.json` écrit ainsi n'est pas lu (le programme repart des réglages par défaut). Écrire sans BOM (`[System.IO.File]::WriteAllText` avec `UTF8Encoding($false)`).
- Un `scriibe.exe` qui tourne verrouille `target\release\scriibe.exe` : l'arrêter avant `cargo build --release` (`Get-Process scriibe | Stop-Process`). Ne jamais lancer deux versions en même temps.
- Pas de `pkill` (sysinfo), pas de `pkill -f` ni de `pgrep -f` avec un motif présent dans la commande (le shell se tue) : `pgrep -x nom | xargs -r kill` ; `pkill -x` refuse un nom de plus de 15 caractères.
- Un `sleep` long en avant-plan est refusé : lancer en arrière-plan ou attendre avec un moniteur. `cmd &` dans un sous-shell détaché fait notifier la fin du lanceur, pas du travail.
- Les tests avec des délais courts attendent large. Les tests de moteurs passent par `FakeWorld` (le temps ne passe que quand on dort).
- `AppSettings::default()` change d'identifiants à chaque appel : ne pas comparer deux défauts.
- `fancy-regex` : pas d'assertions arrière de longueur variable.
- `windows-sys` 0.59 : les poignées sont des pointeurs ; crate `windows` 0.57 pour COM (HRESULT brut : `IsSystemSoundsSession().is_ok()` vaut vrai pour S_OK **et** S_FALSE, comparer à 0).
- `x11rb` : un message envoyé avec `send_event` doit être attendu (`.check()`) avant de fermer la connexion, sinon l'écoute ne s'arrête pas. Un processus enfant lancé sans être attendu reste zombie.
- Depuis le cloud : `gh run view --log-failed` et la recherche GitHub sont refusés ; `gh api` sur d'autres dépôts, kyutai.org, Hugging Face et le stockage des pièces jointes de GitHub ne sont pas joignables. La recherche et les listes de fichiers Hugging Face ne s'essaient que sur le PC.

## Comportement de Scriibe

- **Le crochet clavier de Windows ne reçoit rien quand la fenêtre de Scriibe a le focus** (S06, cause inconnue). Depuis S08 la page relaie ses touches (`api/keys/page`, `Controller::handle_page_key`, ignorées tant que le crochet parle) ; la capture des touches (Réglages) passe par la page (`api/keys/capture/key`). Corollaire : **la pastille ne doit jamais s'activer** (`show()` l'activait quand Scriibe était au premier plan, la fenêtre perdait le focus et la touche tenue était relâchée aussitôt) ; elle s'affiche par `show_without_activating` (`SW_SHOWNA`).
- Le crochet clavier remonte toutes les touches (`KeyEvent::Changed`) ; la machine à états est dans `scriibe_core::hotkey`.
- La touche Lecture/Pause du clavier va au dernier lecteur inscrit (Chrome), pas à celui qui joue.
- **Pause qui ne fait rien avec Chrome alors que le journal dit « pause demandée »** (S09, 30/10/2026) : Chrome venait de se mettre à jour et n'était pas relancé ; il ignorait alors toute commande Lecture/Pause de Windows (touche, API des sessions multimédias, bouton du panneau du volume), alors que son état « Playing/Paused » restait lisible. Relancer Chrome (`chrome://settings/help` → Relancer) a tout remis en marche. Pour trancher : essayer le bouton Pause du panneau du volume de Windows ; s'il ne marche pas non plus, ce n'est pas Scriibe.
- **Texte collé en plusieurs exemplaires** (S13, 01/11/2026) : ce n'est pas le collage (une seule ligne `collage:` par dictée dans le journal, un seul ⌘V envoyé) mais Whisper, dont le serveur court (`-ac 512`) répète parfois la phrase dans sa réponse. Pour le reconnaître : `rawText` de `history.json` contient déjà la répétition. Corrigé par `whisper::repeats_itself` + seconde transcription sur le serveur normal (`docs/ECARTS.md`). Si cela revient : relever la durée de la prise et le serveur, et essayer `SHORT_AUDIO_CTX` à 1024 (aucune boucle en banc, mais moins rapide).
- **Mise à jour des moteurs sur le Mac** (02/11/2026) : `brew upgrade llama.cpp` passe aussi `ggml` (0.25.3 → 0.28.0) et `whisper.cpp` (1.9.4 → 1.9.5), qui en dépendent. Passé de llama.cpp 0.5.0 (build 11146) à 0.8.0 (build 11960) : toutes les options de `crates/engines/src/llama.rs` existent encore, la mise au propre répond ; Whisper 1.9.5 en `-ac 512` boucle toujours (la reprise sur le serveur normal reste nécessaire). Les anciennes versions restent dans `/opt/homebrew/Cellar` (`HOMEBREW_NO_INSTALL_CLEANUP=1`) pour revenir en arrière si besoin.
- Avec « Automatique », `llama-server` choisit la Radeon (2 Go) et s'arrête : le repli sur le processeur est automatique depuis S07.
- Une version du modèle qui arrive après un « Recommencer » du banc ne doit pas rejoindre le nouveau passage (identifiant du passage).
- Le prompt envoyé au modèle doit rester identique d'une dictée à l'autre jusqu'à la dictée elle-même (mémoire du serveur) : rien de variable avant elle.

## Interface en deux langues (S08)

- Un texte de la page sans `t('…')` reste en français quelle que soit la langue ; `i18n.test.ts` échoue pour un `t('…')` sans traduction, une traduction orpheline ou des `{valeurs}` qui diffèrent. Il ne voit pas les textes construits à la volée (`t(variable)`) : les marquer par `tx('…')` à leur définition.
- Un texte envoyé par Rust se traduit dans `locales/en-server.ts` ; un message à valeur (`Aucun son capté — vérifie le micro (Realtek)`) se traduit d'après son modèle (`{name}`), les valeurs connues (« anglais », « Ctrl gauche »…) étant traduites aussi. Les modèles les plus précis doivent venir avant les plus généraux.
- `format.ts` reste en français (le rapport l'utilise) ; la page importe `display.svelte.ts` pour les nombres, tailles et dates.
- Ne pas passer `fmt` à `.map` directement (`.map(fmt)` donne l'indice comme langue).
- `Help.svelte` et `HelpEn.svelte` sont deux fichiers : toute modification de l'un se reporte dans l'autre (le test compare leur structure, pas leur texte).
- Le banc et l'essai d'un mode suivent la **langue dictée** (réglage « Langue dictée »), pas la langue de l'interface : une interface en anglais avec une dictée en français lit des phrases françaises, c'est voulu. Le test de frappe suit la langue de l'interface.

## macOS

- **La touche ne réagit pas, aucune demande d'autorisation (macOS 27)** : le tap CoreGraphics se crée sans erreur mais ne reçoit rien tant que l'autorisation « Surveillance de l'entrée » manque ; `CGPreflightListenEventAccess()` renvoie faux. L'autorisation va au **processus responsable**, pas à l'appli qu'on croit : un Scriibe lancé par l'outil Bash de Claude (même via `osascript` et Terminal) est rattaché à `com.anthropic.claude-code`, sans droits. À faire : que Christophe lance Scriibe **lui-même dans son Terminal** (le quitter et le rouvrir à la main). Diagnostic : `/usr/bin/log show --last 10m --predicate 'process == "tccd"'` et lire `AUTHREQ_ATTRIBUTION` (`responsible=`). Si Terminal est coincé : `tccutil reset ListenEvent com.apple.Terminal`, puis le rajouter avec « + » (Applications → Utilitaires → Terminal). Ne pas modifier les réglages de sécurité depuis la session (refusé).
- `cargo` est dans `~/.cargo/bin`, hors du PATH du shell de Claude : `export PATH="$HOME/.cargo/bin:$PATH"`.
- Lire TextEdit par `osascript` depuis la session bloque (demande d'automatisation invisible) : lire le journal de Scriibe à la place.
- **Pause des médias : la vidéo déjà arrêtée redémarre (S10)** : le son de début de Scriibe (`afplay`) est un processus audio sans bundle qui « joue » ; il déclenchait la pause. Exclu dans `macos/media.rs` (`is_own_sound`). Un autre programme qui sort un bref son peut produire la même chose ; le journal (« médias: pause demandée (…) ») dit qui.
- **VLC (et d'autres) gardent leur flux audio ouvert en pause** : `kAudioProcessPropertyIsRunningOutput` reste vrai, la touche Lecture/Pause relance le lecteur arrêté. Contournement (S10) : `SELF_REPORTING_PLAYERS` dans `macos/media.rs` (VLC, Musique, Spotify) interroge l'appli par AppleScript. Pour un autre lecteur qui ferait pareil, ajouter une ligne (identifiant de bundle + script rendant `true`/`false`). **Chrome garde son flux ouvert environ 10 s après la pause d'une vidéo** (mesuré en S15 avec une fenêtre Chrome d'essai ; la note « une seconde » était fausse) : dicter dans ce délai relançait la vidéo, et la vérification de pause ne pouvait pas conclure. Correctif (S15) : `BROWSERS` dans `macos/media.rs` interroge les pages par `execute javascript` (Apple Events) ; il faut que la personne coche une fois Chrome → Présentation → Développeur → « Autoriser JavaScript provenant d'Apple Events » et accepte l'automatisation de Chrome. Sans réponse, l'ancien comportement reste et le journal le dit (« le navigateur ne répond pas à JavaScript »). Un script lancé par Bash ne peut pas l'essayer (demande d'automatisation invisible) : l'essai se fait avec Scriibe.app. L'API « lecture en cours » de macOS (MediaRemote) répond toujours « non » pour un programme tiers.
- **Collage ignoré par le champ Google de Chrome alors que le journal dit « collage: N signes envoyés »** (S15) : le texte était dans le presse-papiers (⌘V manuel collait), mais Chrome ignorait le ⌘V synthétique composé d'un V portant seulement le drapeau ⌘ (4 échecs sur 5, surtout avec le seul curseur clignotant ; le menu déroulant affiché « réparait »). Ni la pause des médias ni le ⌘C d'essai n'étaient en cause (essais en les coupant). Correctif : vraie frappe ⌘ enfoncé, V, V relâché, ⌘ relâché (`paste.rs::send_command_v`). Le rapport « focus » de l'Accessibilité ne sert à rien avec Chrome (« aucun élément »).
- **macOS redemande l'accès au trousseau après chaque compilation** : la signature ad hoc du binaire change à chaque `cargo build`. Lancer `tools/signer_macos.sh` après la compilation (certificat « Scribe Dev » du trousseau de Christophe), puis répondre une fois « Toujours autoriser ». Un `.app` signé avec le même certificat tiendrait aussi les autorisations (touche, micro) à son nom.
- **Scriibe.app lancée par `open` depuis la session (S11)** : contrairement à un programme lancé par Bash, elle est son propre processus responsable (`tccd` : `responsible=fr.scriibe.app`) ; les autorisations se demandent à elle et tiennent d'une compilation à l'autre (`tools/faire_app_macos.sh`, signature « Scribe Dev »). Sans « Surveillance de l'entrée », la page affiche maintenant le message (le tap se crée sans erreur, `CGPreflightListenEventAccess` le dit). Relancer Scriibe après l'avoir accordée. Le trousseau redemande « Toujours autoriser » une fois par clé, car l'identité du `.app` (`fr.scriibe.app`) n'est pas celle du programme seul (`fr.scriibe.cli`).
- **Deux instances sur Mac (S11)** : le verrou est un `flock` sur `instance.lock`, mais le programme d'avant S11 (lancé depuis un Terminal) ne le prend pas : fermer l'ancien avant de lancer le `.app`, sinon deux collages.
- **Compiler Scriibe.app** : `cd ui && npm run build`, `cargo build --release`, `tools/faire_app_macos.sh` (ferme l'ancienne, installe dans `~/Applications`, ajouter `--lancer`). L'assemblage se fait hors de Documents (iCloud remet des attributs que `codesign` refuse).

## Linux

- **`whisper-server` posé à la main n'est pas vu** : le chemin du moteur n'est cherché **qu'au démarrage** (`WhisperLauncher::new`) ; relancer Scriibe après l'avoir posé. Le dossier des moteurs est `~/.local/share/Scriibe/engines/whisper/` (**S majuscule**, `APP_NAME`), alors que les données sont dans `~/.local/share/scriibe/` (minuscule) : ne pas confondre.
- **Texte sans rapport avec la dictée, niveau 1,000 dans le journal** : micro intégré saturé. Sur le HP ProBook 450 G6 (Ubuntu 26.04), ALSA réglait `Capture` à +30 dB **et** `Internal Mic Boost` à +30 dB. Corrigé par `amixer -c 0 sset 'Internal Mic Boost' 1` et `amixer -c 0 sset Capture 40` (environ +23 dB en tout). À faire : avertir dans la page quand le niveau reste collé au maximum (saturation), comme on avertit déjà d'un micro trop faible.
- Pas de `pactl` sur Ubuntu 26.04 de base (PipeWire seul, `wpctl`) : la pause des médias qui le lit ne trouvera rien (à vérifier).
- Dans la session de Claude Code : `sudo` demande un mot de passe qu'on ne peut pas taper ; ouvrir une fenêtre `gnome-terminal -- script.sh` où Christophe le tape. Le contrôle de sécurité refuse aussi de compiler du code téléchargé (whisper.cpp) : préparer un script et le faire lancer par Christophe avec `! bash ~/script.sh`.
- **Micro muet ou au maximum en changeant de session** : en revenant sous GNOME, le gain d'ALSA était revenu à +30 dB + +30 dB, et la source **coupée** (`wpctl status` : `MUTED`) ; Scriibe disait « Aucun son capté ». `wpctl set-mute @DEFAULT_AUDIO_SOURCE@ 0` et `amixer -c 0 sset Capture cap` (puis le gain, plus haut). Le réglage de gain ne tient donc pas d'une session à l'autre.
- **Wayland, fenêtre du raccourci de GNOME** : une touche de modification seule (Ctrl droit) n'est pas acceptée, et l'ancien raccourci proposé disparaît pendant la saisie ; il faut une combinaison avec une touche ordinaire. Le raccourci se change dans **Paramètres → Applications → Scriibe → Raccourcis clavier** (pas dans Clavier → raccourcis). Le portail est en version 1 : `ConfigureShortcuts` n'existe pas. Dans cette fenêtre, il faut cliquer **Add** après avoir tapé la combinaison : sinon GNOME ne garde rien et Scriibe attend sa réponse sans dicter (journal sans ligne « portails: raccourci … accepté »).
- **Wayland, déconnexion** : quitter la session ferme aussi la session de Claude Code et Scriibe ; la reprendre avec `claude --continue` dans un Terminal ouvert dans le dossier personnel.
- **ashpd** : les portails sont derrière des options (`global_shortcuts`, `remote_desktop`, et `screencast` dont `remote_desktop` a besoin).

- **Micro USB branché : il devient la source par défaut** (`wpctl status`, astérisque) et Scriibe l'écoute (`default`) sans rien dire ; un micro USB à -14 dB (`amixer -c 1 sget Mic`) donnait « Aucun son capté » (niveau 0,001). Monté par `amixer -c 1 sset Mic 100%` et `wpctl set-volume <id> 1.0` : niveau 0,06, texte juste. À faire : afficher dans la page le nom du micro réellement utilisé derrière `default`.
- **Roue dentée dans le dock de GNOME** : le `.desktop` doit porter `Icon` et `StartupWMClass` égal à la classe de la fenêtre (`Scriibe` sous XWayland, `xprop -id <fenêtre> WM_CLASS`). Ne pas lancer `gtk-update-icon-cache` sur `~/.local/share/icons/hicolor` : le cache figé masquerait les icônes posées ensuite.
- **Arrêter Scriibe par `kill` laisse `whisper-server` et `llama-server` tourner** (orphelins) ; au lancement suivant, `llama-server` échoue une fois (port pris) avant que Scriibe les ferme (`kill_matching`). Quitter par le menu de l'icône ou `POST api/quit`.
- **Wayland, relâchement du raccourci jamais reçu** (pastille « J'écoute » qui reste) : voir `ESSAI_LINUX.md` (04/11) ; lire `journalctl --user -o cat | grep portails` quand Scriibe a été lancé par la liste des applications (sa sortie va dans le journal de la session).
- **Pastille sous Linux (XWayland)** : `set_ignore_cursor_events` sur une fenêtre jamais montrée fait s'arrêter Scriibe net (tao, `window().unwrap()` sur `None`, panique qui ne peut pas remonter) ; sous Linux, l'appeler après `show()`.
- **Fenêtre Tauri sous Linux** : il faut `libwebkit2gtk-4.1-dev` et `libayatana-appindicator3-dev` pour compiler (CI et Release aussi). Au lancement, `libayatana-appindicator is deprecated` et `Gtk-CRITICAL … gtk_widget_get_scale_factor` s'affichent : sans effet visible (fenêtre, icône et dictée marchent).
