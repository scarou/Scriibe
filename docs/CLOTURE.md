# Clôture, publication et essais : détails

Sorti du `CLAUDE.md` (règle R03). À lire en clôturant une session, en publiant une version, ou en faisant un essai sur le PC ou le Mac de l'auteur.

## Clôture et CI

- **Minutes GitHub Actions** : depuis le **02/11/2026 le dépôt est public**, donc les minutes des exécuteurs standard sont gratuites : plus de `[skip ci]` obligatoire ni de limite à une CI complète par session (l'ancien forfait des dépôts privés, épuisé jusqu'au 01/11/2026, ne s'applique plus). Elle lance à chaque envoi Linux, les cas de référence et `scriibe.exe` ; Windows et macOS complets à la main (`gh workflow run ci.yml --repo scarou/Scriibe`) avant une clôture **seulement si la session a changé du code propre à un système (`crates/platform`, `pipeline`, `cli`), des tests ou des dépendances** ; pour une session de documentation ou de texte d'interface, la CI Linux de l'envoi suffit. **Compilation sur le PC** : session Claude Code locale dans `C:\scriibe-dev` (`git pull`, `cd ui && npm ci && npm run build`, `cargo build --release`, exécutable `target\release\scriibe.exe` ; fermer la version en cours avant) ; `C:\scriibe` garde le `scriibe.exe` de la mise à jour par la fenêtre. **Publier une version** : numéro dans `Cargo.toml`, compiler, commiter, pousser, puis `tools/publier_macos.sh x.y.z` (aperçu puis « oui » de l'auteur) ; le workflow `release-windows.yml` ajoute alors `scriibe-windows-x64.zip` à la Release.
- Clôturer : mettre à jour `CHANGELOG.md` (une section par session), `REPRISE.md`, `ROADMAP.md`, `README.md` (état), `docs/ECARTS.md` et `fixtures/A_FAIRE.md` ; `cargo fmt --all`, `cargo clippy --all-targets -- -D warnings`, `cargo test --workspace` ; pousser, puis `tools/attendre_ci.sh` (la CI doit être verte ; sur les trois systèmes par un lancement manuel, dans les cas ci-dessus) ; renommer la session « Snn - jj/mm/aaaa - Titre ».
- `tools/attendre_ci.sh` se lance directement avec `run_in_background` (dans un sous-shell détaché, la notification annonce la fin du lanceur et non celle de la CI).

## Essais sur les machines de l'auteur

- Essais sur le PC de l'auteur : un seul écran, copier-coller pénible ; passer par l'interface plutôt que par des commandes, et donner une étape à la fois. Rien n'est téléchargé sans son accord (taille et source annoncées ; la page demande une confirmation).
- Mises à jour de `scriibe.exe` sur le PC de l'auteur : **par la fenêtre de Scriibe** (onglet « Mise à jour » : « Chercher une nouvelle version », « Installer et redémarrer »), plus de zip à la main ; elle prend la dernière **Release** publiée sur GitHub (S14 : plus de jeton, le dépôt est public ; le zip `scriibe-windows-x64.zip` est ajouté à la Release par le workflow `release-windows.yml`, donc attendre qu'il ait fini avant de lui dire de mettre à jour). Un jeton GitHub déjà rangé dans son Gestionnaire d'identifiants n'est plus utilisé : ne jamais le lire. Une nouvelle fonction de l'interface se teste avec lui : une étape à la fois, puis « Copier le rapport ». Rapport (onglet « Journal et rapport », « Copier le rapport ») = état + résultats du banc + journal + `llama-server --list-devices`.
- Chaque essai chiffré : plusieurs dictées (les séries varient autant que les écarts entre configurations), jamais une seule.
- **Sessions sur le Mac de l'auteur** (macOS, `~/Documents/Mes projets IA/Scriibe-dev/Scriibe`) : prompt en tête de `REPRISE.md`, compilation, `Scriibe.app` et autorisations dans `docs/ESSAI_MACOS.md` ; journal : `~/Library/Application Support/Scriibe/scriibe.log` (à lire soi-même). Les autorisations vont à Scriibe.app, lancée par `open` (rien par Bash, `docs/PIEGES.md`) ; l'auteur les donne par un clic puis une relance ; lui seul tient la touche et parle.
